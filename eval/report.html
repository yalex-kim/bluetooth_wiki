Issues Found & Wiki Improvement Opportunities
Q024 · WIKI BUG Continuation_Number range incorrect in ble-parameters.md
The wiki's ble-parameters.md states Continuation_Number range as 0–499, but the Bluetooth Core Spec defines it as 0–15. This is a factual error that causes the wiki to give wrong implementation guidance.
Update ble-parameters.md Continuation_Number range to 0–15 (0x00–0x0F).
Q008 · PHRASING GAP Subrating stacking formula not stated explicitly
connection-management.md demonstrates Connection Subrating using Peripheral_Latency in examples but never states the explicit formula: Effective_Interval = Connection_Interval × Subrate_Factor × (1 + Continuation_Number).
Add the formula explicitly to connection-management.md §Connection Subrating.
Q020 · AMBIGUITY RPA origin version (4.0 vs 4.2) unclear
The wiki's security.md notes RPA existed since 4.0 but 4.2 added controller-based resolution. The privacy evolution timeline is ambiguous — the page does not clearly state which version "introduced" RPA for typical use.
Add explicit timeline callout: "RPA defined in 4.0; controller-based resolution (Enhanced Privacy) added in 4.2."
Q023 · INCOMPLETE SEQUENCE BIS setup sequence shows 7 steps, reference expects 9
hci-sequences.md section 7a lists 7 numbered steps for BIS setup, omitting two discrete steps: (2) Set Extended Advertising Data and (4) Set Periodic Advertising Data as separate enumerated items.
Expand hci-sequences.md BIS setup to 9 explicit steps, matching the canonical sequence.
Q028 · FORMULA CONFUSION Continuation_Number vs Max_Latency conflated in supervision timeout explanation
The wiki does not clearly distinguish Continuation_Number from Max_Latency (Peripheral_Latency in subrated units). Both appear in supervision timeout formulas but serve different roles. This caused a minor hallucination penalty (−1) in the edge case response.
Add a disambiguation note in connection-management.md clarifying Continuation_Number (additional consecutive active events) vs Max_Latency (skipped subrated events for peripheral latency).
